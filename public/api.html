API & Integrations

VSBIL's API is designed for authenticated, auditable integrations. Public documentation is intentionally descriptive until production credentials, scopes and rate limits are formally published.

Authentication

Protected endpoints require authenticated sessions or approved service credentials. Secrets must remain server-side. API consumers must never place service-role keys, Paystack secret keys, Google client secrets or OAuth refresh tokens in browser code.

Core API domains

  • Authentication: registration, login, email verification and session security.
  • Users: profile, account state and preferences.
  • YouTube: OAuth connection, channel state and supported verification operations.
  • Activities: campaign discovery, submissions and verification.
  • Wallet: authoritative balance and transaction history.
  • Payments: activation transactions and provider verification.
  • Withdrawals: requests, review state and payout reconciliation.
  • Referrals: qualification and reward records.
  • Admin: privileged moderation, financial review and audit operations.

API design principles

Endpoints should validate input, authorize the current actor, enforce rate limits, return safe errors, avoid leaking secrets and produce an auditable event for security-sensitive actions. Financial operations must be idempotent and backed by database transactions or equivalent atomic mechanisms.

Webhooks

Payment-provider webhooks must be authenticated/verified, deduplicated and processed idempotently. A webhook should never trust an amount or status supplied by an unverified browser request.

Rate limits

Rate limits may differ by endpoint and risk level. Authentication, verification-code, password-reset, withdrawal and administrative endpoints should have stricter controls than ordinary read operations.

YouTube integration

YouTube access is granted through OAuth scopes approved by the user. VSBIL uses only supported APIs and must respect provider quotas, data policies and revocation. API availability does not imply that YouTube will count an action toward monetization.

Versioning

Production APIs should be versioned before external publication. Breaking changes should receive a migration notice and a documented deprecation period where practical.

Responsible use

Do not use the API to scrape private data, automate prohibited engagement, bypass marketplace controls, create fraudulent accounts, manipulate wallets or overload the service.

Developer access

External API access should be granted only through an approved application or integration process. Credentials can be revoked when compromised, inactive or used contrary to policy.
