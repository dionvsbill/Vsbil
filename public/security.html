SECURITY & TRUST

Security & Responsible Disclosure

Version 1.0 · Effective August 29, 2026

Security objective

VSBIL treats account identity, OAuth credentials, payments, wallet balances, withdrawals and administrative actions as security-sensitive. The platform is designed so that authoritative financial and authorization decisions occur on the server rather than in browser-controlled state.

Account protection

Authentication should use protected sessions, verified credentials and appropriate rate limits. Users should use a unique password, protect verification codes and immediately report suspected account compromise.

OAuth protection

Google and YouTube connections use OAuth. Access and refresh credentials, where required, are stored server-side in encrypted form. VSBIL does not need a user's Google password to connect the service.

Payment security

Payment status is verified server-side. Provider webhooks should be validated and processed idempotently so the same payment cannot activate an account or credit a financial benefit twice.

Wallet integrity

Wallet changes should be represented by authoritative ledger entries. Negative balances are restricted by database constraints and withdrawal operations should reserve funds before review. Client-side balance values are never treated as proof of entitlement.

Administrative security

Administrative actions should use role-based authorization and generate audit records. Sensitive operations include user suspension, reward changes, campaign moderation, withdrawal approval, settings changes and access to financial information.

Monitoring

Security events may record timestamps, account references, IP addresses, user-agent information and structured metadata when needed for protection and investigation. Monitoring is subject to the Privacy Policy and applicable law.

Responsible disclosure

If you discover a vulnerability, report it privately through VSBIL's designated support/security channel. Provide a clear description, affected endpoint or feature, reproducible steps and potential impact. Do not access unrelated accounts, copy private information, destroy data, deploy malware or intentionally disrupt availability.

Incident response

Security incidents may trigger containment, credential rotation, session revocation, provider notification, investigation, user communication and other response measures appropriate to the incident and legal requirements.

No absolute-security promise

Security controls reduce risk but cannot eliminate every threat. Users are responsible for protecting their own credentials and devices and for reporting suspicious activity promptly.
